# my-render

`my-render` — учебный программный 3D-рендерер, написанный на C++20. Проект создан для изучения базовых этапов графического конвейера: преобразования вершин, перспективной проекции, clipping, растеризации треугольников, проверки глубины, текстурирования, материалов и освещения.

Рендеринг выполняется на CPU в собственный framebuffer. OpenGL используется только для вывода полученного изображения в окно, а GLFW — для создания окна и обработки ввода.

## Возможности

- загрузка простых моделей в формате OBJ;
- поддержка MTL-материалов: `mtllib`, `usemtl`, `Ka`, `Kd`, `Ks` и `Ns`;
- программная растеризация треугольников;
- color buffer и z-buffer;
- clipping по шести границам пирамиды видимости;
- перспективно-корректная интерполяция атрибутов;
- наложение текстур;
- ambient, diffuse и specular-составляющие освещения с параметрами из материалов;
- многопоточная обработка геометрии и растеризация через общий thread pool;
- преобразования model, view и projection;
- собственная математическая библиотека:
  - `Gfloat` для сравнения чисел с плавающей точкой с учётом погрешности;
  - векторы `Vec2`, `Vec3` и `Vec4`;
  - матрицы `Mat3` и `Mat4`;
  - кватернионы;
  - операции перемещения, вращения, масштабирования и проекции;
- свободное перемещение и вращение камеры;
- юнит-тесты математической библиотеки на GoogleTest.

## Учебная сцена

В демонстрационной сцене используется текстурированный куб из `cube.obj`. Геометрия ссылается на `cube.mtl`, а материал выбирается для каждого треугольника с помощью `usemtl`.

> **Один треугольный полигон куба специально сделан почти чёрным.** Он использует отдельный материал с низкой ambient-составляющей и нулевыми diffuse/specular-составляющими. Это намеренная демонстрация назначения разных материалов отдельным полигонам, а не ошибка UV, освещения, clipping или растеризации.

Остальные полигоны используют основной материал с параметрами `Ka = 0.4`, `Kd = 0.7`, `Ks = 0.3` и `Ns = 32`.

## Управление

Перемещение камеры:

| Клавиши | Действие |
|---|---|
| `↑` / `↓` | движение вверх / вниз |
| `←` / `→` | движение влево / вправо |
| `Z` / `X` | движение вперёд / назад |

Вращение камеры:

| Клавиши | Действие |
|---|---|
| `W` / `S` | наклон вверх / вниз (pitch) |
| `A` / `D` | поворот влево / вправо (yaw) |
| `Q` / `E` | крен влево / вправо (roll) |

## Зависимости

Для сборки необходимы:

- компилятор с поддержкой C++20;
- CMake 3.16 или новее;
- OpenGL;
- GLFW 3;
- GoogleTest — только для сборки тестов.

Исходники GLAD и stb_image уже находятся в репозитории.

Пример установки зависимостей для Ubuntu/Debian:

```bash
sudo apt install build-essential cmake libglfw3-dev libgl1-mesa-dev libgtest-dev
```

## Сборка и запуск

Из корня репозитория выполните:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
cd build
./my-render
```

Приложение следует запускать из каталога сборки: в текущей версии пути к демонстрационным OBJ-модели и текстуре задаются относительно него.

## Запуск тестов

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build -j
ctest --test-dir build --output-on-failure
```

Чтобы собрать проект без GoogleTest:

```bash
cmake -S . -B build -DBUILD_TESTING=OFF
cmake --build build -j
```

## Структура проекта

```text
include/
├── engine/          # framebuffer, OBJ/MTL-загрузчик, thread pool, текстуры и растеризатор
└── glm-like-lib/    # векторы, матрицы, кватернионы и преобразования
    └── unit_tests/  # тесты математической библиотеки
src/
└── glad.c           # загрузчик функций OpenGL
cube.obj             # геометрия и UV учебного куба
cube.mtl             # материалы учебного куба
texture.png          # текстура демонстрационной сцены
main.cpp             # окно, управление камерой и демонстрационная сцена
```

## Текущие ограничения

- OBJ/MTL-загрузчик поддерживает только необходимое для демонстрационной сцены подмножество форматов;
- `map_Kd` пока не поддерживается: текстура загружается отдельно в коде сцены;
- пути к ресурсам и параметры сцены пока задаются непосредственно в коде;
